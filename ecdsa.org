* Elliptical Curve Digital Signature Algorithm

** Elliptical curves                                              :secp256k1:

Defined by mathematical functions such as y² = x³ + ax + b

In cryptography, a specific curve used is =secp256k1=
with coefficients a = 0 and b = 7, meaning the function becomes

y^{2} = x^{3} + 7

** Generator Point (G)

The generator point is a predefined fixed point on the elliptical
curve that is publicly known and is the starting point of all
mathematical operations.

For =secp256k1= they are:

x = 0x79BE667EF9DCBBAC55A06295CE870B07029BFCDB2DCE28D959F2815B16F81798

y = 0x483ADA7726A3C4655DA4FBFC0E1108A8FD17B448A68554199C47D08FFB10D4B8

** Order (n)

The order is a large prime number that represents the size of possible
private public key pairs generated by G in the =secp256k1= curve.

When G is added to itself repeatedly, it will give n unique points
until it starts repeating.

The order n is an emergent property of the selected generator point G
and the curve's equation.

G added to itself represents scalar multiplication e.g.

2G = G+G, 3G = 2G + G etc

Therefore the private key is the multiple of G and the public key is
the resulting product i.e.

pubKey = privKey * G

The private key is an integer between 1 and n-1

** Elliptical Curve Discrete Logarithmic Problem (ECDLP)              :ecdlp:

ECDLP states that given a public key pubKey  and generator point G,
it is computationally infeasable to find private key p in the equation

pubKey = p * G

This is one-way property is what secures ECDSA's security


** ECDSA Signing

Three values are used for signing and verifying signatures: v, r and s

*** r

A random nonce k in the order of G (1 to n-1) is selected. It is used
to calculate a point R

R = k * G

r is the x-coordinate of the resulting point. Note that since the
curve is symmetric with respect to the x-axis, each r value
has two possible y values on the curve.

*** s

s is calculated from the private key, the r value, the random nonce k
and the hash of the message. The private key is embedded within s
proving the signer without revealing it.

*** v

v (recovery id) indicates with of the two possible y-coordinates
assocated with r (i.e. the public signature R) was used for the
signature. It enables recovery of the signers public key (and
subsequently their address in ethereum)


The (v, r, s) tuple is the digital signature of the message.


** Signature Malleability

Because of the secp256k1's curve symmetry, i.e. for a given r there
are two possible y coordinates, it is possible that for a given (v, r,
s) tuple, an attacker can craft a matching (v', r, s') tuple.

This can enable replay attacks.

A common mitigation is to limit s to one of two possible values i.e.

s <= n/2
