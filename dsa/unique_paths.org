* Unique Paths

** Description

https://neetcode.io/problems/count-paths/question

* Top Down Dynamic Programming with Memoization

*** Approach

- Recursively calculate unique paths from each position in board
- Unique paths from the target itself is 1
- a position out of bounds gives no path
- unique path for any other position is sum of paths from right and
  bottom cells

*** Solution

#+begin_src python
class Solution:
    def uniquePaths(self, m: int, n: int) -> int:
        self.grid = [[-1] * n for _ in range(m)]
        self.nrows = m
        self.ncols = n
        return self.find_unique(0, 0)

    def find_unique(self, i, j):
        if i >= self.nrows or j >= self.ncols:
            # out of bounds
            return 0
        if i == self.nrows - 1 and j == self.ncols - 1:
            # target
            return 1
        if self.grid[i][j] != -1:
            return self.grid[i][j]

        self.grid[i][j] = self.find_unique(i, j+1) + self.find_unique(i+1, j)
        return self.grid[i][j]

* Bottom Up Dynamic Programming

*** Approach

- Calculate unique paths working backwards from target
- Bottom and rightmost rows will be ones (only one unique path to target)
- For all other cells, add values from bottom and right cells

*** Solution

#+begin_src python
class Solution:
    def uniquePaths(self, m: int, n: int) -> int:
        row = [1] * n
        for _ in range(m-1):
            new_row = [1] * n
            for col in range(n-2, -1, -1):
                new_row[col] = new_row[col + 1] + row[col]
            row = new_row
        return row[0]

* Combinatorial Solution (Closed Form)

*/ Approach

Any path from (0,0) to (m-1, n-1) consists of exactly (m-1) down moves
and (n-1) right moves, in some order. So each unique path corresponds
to a choice of which of the (m + n - 2) total moves are "down":

    answer = C(m + n - 2, m - 1)   (equivalently C(m + n - 2, n - 1))

We compute the binomial coefficient iteratively using

    C(n, k) = product over i of (n - k + i) / i   for i = 1..k

which keeps a running integer (the division is exact at each step), so
no big-integer/float issues, and we use the smaller of k = m-1 or n-1
for fewer iterations.

*/ Solution

#+begin_src python
class Solution:
    def uniquePaths(self, m: int, n: int) -> int:
        # total moves = (m-1) down + (n-1) right; choose where the down moves go
        total = m + n - 2
        k = min(m - 1, n - 1)
        result = 1
        for i in range(1, k + 1):
            # result = C(total - k + i - 1, i) at step i; exact division
            result = result * (total - k + i) // i
        return result
