* Container Most Water

** Description

https://neetcode.io/problems/max-water-container/question

** Approach

The naive approach would be to try all possible areas between each
two subsequent points and find the largest.

This would be an O(n^{2}) time complexity.

To optimize for length, we'd want to pick points that are
farthest from each other. To optimize for height, we'd want to pick
the tallest points.

Problem, how do we recognize the tallest points to optimize the height?

_AI_:


Consider that the area between two lines is limited by the shorter
one.  Starting with the widest possible container (leftmost and
rightmost lines), ask: if you move a pointer inward, which move could
/potentially/ increase the area?

But how do we know when to stop?

_AI_:


When the two pointers meet, you've considered every possible
pair that could have a larger area—since moving the taller line never
helps, you only need to try each line as the shorter side once.

Yes, that's right. At each step you compute area using the current

** Solution

#+begin_src python
from typing import List

class Solution:
    def maxArea(self, height: List[int]) -> int:
        n = len(height)
        left, right = 0, n - 1
        max_area = 0
        while left < right:
            min_height = min(height[left], height[right])
            area = min_height * (right - left)
            if area > max_area:
                max_area = area
            if height[left] > height[right]:
                right -= 1
            else:
                left += 1
        return max_area

height = [1,8,6,2,5,4,8,3,7]
print(Solution().maxArea(height))
# Output: 49

height = [1,1]
print(Solution().maxArea(height))
# Output: 1

height = [5,5,5,5]
print(Solution().maxArea(height))

height = [1,2,3,4,5]
print(Solution().maxArea(height))

** Analysis

*** Time complexity

- Since we're traversing the array inward from both ends till they meet
  we need O(n) steps to identify each area. We're doing constant time work
  to calculate each area, so time complexity is O(n).

*** Space complexity

- We are using a few additional variables to track area and positions
  as we traverse the array. Space complexity is therefore O(1) constant.

_Me_:

Is this analysis correct?

_AI_:

Yes, correct. One small nuance: the loop runs n steps (left travels
rightwards, right travels leftwards, each step advances one pointer
until they meet). So exactly O(n) time, and O(1) extra space.

_AI_:

Consider early termination: if the current max area is already large
enough, you might skip some moves, but generally not needed for
O(n). Another optimization: skip duplicates of the same height when
moving pointers, since moving to the same height will not increase
area. For example, if height[left] == height[right], moving either
pointer is fine, but you can skip consecutive equal heights. But the
current solution already works and is optimal in terms of asymptotic
